## 一、使用前先了解四個區域

StallPay T7 測試網站將「網路連線確認」、「主管憑證管理」、「現場流程模擬」與「情境測試產出」分開處理。使用者應依角色操作，不要將主管管理碼、測試授權碼或天來 Token 填入一般測試欄位。

| 區域 | 主要用途 | 可操作角色 | 是否接觸正式設備 |
|---|---|---|---|
| 機台網路與天來 API 唯讀檢查 | 確認 Adapter、DNS、HTTPS／TLS、Machine API、Commodity API | 現場測試工程師 | 只讀取，不控制 |
| 高層主管設定 `SUPER_ADMIN` | 建立、查看遮罩狀態或回滾 company／token 版本 | 高層主管 | 只管理伺服器憑證 |
| 現場無人銷售流程與機台回報 | 模擬掃描 QR、驗證、開門、鎖貨、取貨與資訊回報 | 測試工程師 | 純模擬 |
| 自助式測試工作台 | 執行十二種安全情境並匯出去敏證據 | 測試工程師、覆核人員 | 純模擬 |

### 角色與權限

| 角色 | 可以做的事 | 不可以做的事 |
|---|---|---|
| 高層主管 `SUPER_ADMIN` | 使用主管管理碼讀取遮罩狀態、建立新的 company／token 版本、依版本 ID 回滾 | 不應將 Token 或主管管理碼交給一般測試人員 |
| 現場測試工程師 `TESTER` | 使用測試授權碼執行 Machine／Commodity 唯讀 preflight、操作模擬情境、匯出去敏結果 | 不可查看或修改 company／token，不可把模擬結果宣稱為實機完成 |
| Dennis／測試結果負責人 | 確認現場證據、判斷是否符合下一階段條件、簽核實機測試結果 | 不可只憑網站模擬或網路連通就解除 GATE-06 |
| 業務或觀察人員 | 查看模擬流程與結果說明 | 不應取得任何管理碼、授權碼或 Token |

## 二、使用前準備

請使用可正常開啟 HTTPS 網站的最新版 Chrome、Edge 或 Safari。現場網路必須允許瀏覽器連到測試網站；唯讀 preflight 則由伺服器連到天來 API，現場電腦不需要保存 company 或 Token。

| 準備項目 | 負責人 | 使用方式 | 安全要求 |
|---|---|---|---|
| 測試網址 | 全體人員 | 開啟 `https://go.stall.merchcore.ai/t7-test` | 只使用 HTTPS 網址 |
| 主管管理碼 | 高層主管 | 用於 `SUPER_ADMIN` 區 | 不貼入對話、不放入截圖、不寫入測試報告 |
| 天來 Company／Token | 高層主管 | 首次建立或輪替 credential 版本時輸入 | Token 只在主管區單次輸入 |
| 測試授權碼 | 現場測試工程師 | 執行真實唯讀網路檢查時輸入 | 不放入匯出檔或現場備註 |
| 現場測試資料 | 測試工程師 | 設備角色、設備識別、場域、貨道、SKU、溫度與庫存 | 不確定內容填 `[TODO: 待人工確認]` |
| 證據保存位置 | 測試結果負責人 | 保存去敏 JSON、CSV 與現場紀錄 | 不保存 Token、sign、管理碼或授權碼 |

> **憑證交接原則：**主管管理碼與測試授權碼應透過核准的安全交接方式提供。天來 Token 不應透過一般對話、Email 內文、公開文件、Git、截圖或 JSON／CSV 測試產出傳遞。

## 三、建議的完整操作順序

| 順序 | 操作 | 執行人 | 預期結果 |
|---:|---|---|---|
| 1 | 開啟正式測試網址 | 測試工程師 | 顯示「天來無人銷售測試模式」與黃色測試警示 |
| 2 | 按「只檢查 Adapter」 | 任一測試人員 | 確認雲端服務是否可用，以及 credential 是否已完成設定 |
| 3 | 若顯示「設定未完成」，由主管建立 credential 版本 | 高層主管 | 頁面顯示 `token=已設定` 與 active version ID |
| 4 | 輸入測試授權碼並按「執行真實唯讀網路檢查」 | 測試工程師 | 顯示 DNS、HTTPS／TLS、Machine API、Commodity API 結果 |
| 5 | 填寫現場資料並儲存設定 | 測試工程師 | 自助式工作台可開始執行情境 |
| 6 | 執行現場流程模擬或十二情境套件 | 測試工程師 | 產生 UTC、狀態序列、機台變化與安全判定 |
| 7 | 匯出去敏 JSON／CSV | 測試工程師 | 本機取得不含 credential 的測試證據 |
| 8 | 由 Dennis 覆核；實機測試未完成前維持 GATE-06 | 測試結果負責人 | 不宣稱 `TEST_DEVICE_VERIFIED` |

## 四、高層主管：首次設定 Company／Token

此步驟只有持有主管管理碼的人員可以執行。一般測試工程師不需要、也不應取得天來 Token。

### 4.1 建立新的 credential 版本

1. 開啟測試頁後，展開 **「高層主管設定 SUPER_ADMIN」**。
2. 在「主管管理碼」輸入本次核准的主管管理碼。
3. 確認「Company」欄位。現行 bootstrap 預設為 `2000162`；若天來另有正式通知，應以主管確認的資料為準。
4. 在「Token」輸入現有天來 Token。Token 欄位不會顯示既有值，也不會由伺服器回傳。
5. 在「變更原因」填寫可稽核原因，例如「首次啟用天來唯讀網路測試」或「天來測試憑證輪替」。
6. 按 **「儲存新版本」**，閱讀確認訊息後再確認。
7. 頁面應顯示「設定已更新」、active version ID、遮罩後 company，以及 `token=已設定`。

| 成功後的行為 | 說明 |
|---|---|
| Token 欄位清空 | 防止憑證留在瀏覽器畫面 |
| 主管管理碼欄位清空 | 每次敏感操作都必須重新授權 |
| 建立新的 active version | 舊版本保留，供必要時回滾 |
| 寫入 UTC audit log | 記錄操作種類、版本與去識別 actor 資訊，不保存明文 Token |

> 若頁面顯示「設定更新失敗」，**舊版本仍維持有效**。不要連續重按，也不要把 Token 貼到其他欄位；先確認 Adapter 狀態、主管管理碼與網路，再重新執行一次受控操作。

### 4.2 讀取遮罩狀態

每次讀取都要重新輸入主管管理碼，再按 **「讀取遮罩狀態」**。正常結果包含 active version ID、遮罩後 company、Token 是否已設定，以及最後更新 UTC。頁面不會顯示 Token 明文。

| 畫面狀態 | 意義 | 處理方式 |
|---|---|---|
| `active version=NONE` | 尚未建立可用版本 | 依 4.1 建立新版本 |
| `token=未設定` | 無法執行天來唯讀查詢 | 由主管輸入現有 Token 建立新版本 |
| `token=已設定` | 可交由 TESTER 執行唯讀 preflight | 不代表實機或出貨已驗證 |
| 「主管管理碼無效」 | 本次驗權失敗 | 停止操作，向授權主管確認，不在一般訊息傳碼 |

### 4.3 回滾至既有版本

回滾只在新版 credential 無法使用，且已確認某個歷史版本應恢復時執行。主管需輸入主管管理碼、目標「回滾版本 ID」與「變更原因」，再按 **「回滾版本」**並確認。

系統不會覆寫歷史資料，而是建立一個新的 active 回滾版本與 audit log。回滾不需要重新輸入舊 Token；若目標版本 ID 不正確，應停止並重新核對，不要猜測版本編號。

## 五、現場測試工程師：執行唯讀網路 Preflight

### 5.1 先檢查 Adapter

按 **「只檢查 Adapter」**不需要輸入授權碼，也不會呼叫天來 API。這一步只確認雲端服務、資料庫、RBAC 與 credential 設定狀態。

| Adapter 狀態 | 意義 | 下一步 |
|---|---|---|
| `READ_ONLY_TEST_ADAPTER`／可用 | Adapter 可接受受控請求 | 輸入測試授權碼執行唯讀 preflight |
| 「設定未完成」 | Adapter 可連線，但尚無 active company／token | 通知高層主管完成第四章 |
| 健康檢查失敗 | 網頁無法取得 Adapter 狀態 | 保留發生時間與畫面狀態，通知主管；不要改用不受控網址 |

### 5.2 執行真實唯讀網路檢查

1. 在「測試授權碼」輸入主管提供的 TESTER 授權碼。
2. 按 **「執行真實唯讀網路檢查」**。
3. 等待 DNS、HTTPS／TLS、Machine API 與 Commodity API 四個欄位更新。
4. 抄錄或保存執行 UTC、測試編號與去敏結果；授權碼欄位會在執行後清空。

| 檢查項目 | 代表意義 | 不代表的事項 |
|---|---|---|
| DNS | 伺服器可解析天來 API 網域 | 不代表機台可收到控制指令 |
| HTTPS／TLS | 伺服器可建立受保護連線 | 不代表設備型號、韌體或協定已正式確認 |
| Machine API | `Machine.aspx` 唯讀查詢可回應 | 不代表 QR 開門、鎖貨或出貨已完成 |
| Commodity API | `Commodity.aspx` 唯讀查詢可回應 | 不代表正式庫存已寫入或對帳完成 |

> **唯讀 preflight 通過，只能標示「天來 API 唯讀連通已驗證」。**不得改標為 `TEST_DEVICE_VERIFIED`，也不得解除 `GATE-06`。

### 5.3 唯讀檢查失敗時

若畫面顯示「測試授權碼無效」，表示本次沒有執行天來 API 查詢。若顯示「唯讀網路 preflight 失敗」，請保留 UTC、DNS、TLS、Machine、Commodity 畫面結果與測試編號，交由主管確認。

不要連續重按、不要自行修改 company／token、不要改用文件中的其他 endpoint，也不要將 `Coupon.aspx`、`ActiveCoupon.aspx`、`VipOrder.aspx` 或 `Sales.aspx` 當成已核准的控制 API。現階段只允許 `Machine.aspx` 與 `Commodity.aspx` 的簽章 GET 唯讀檢查。[2] [3]

## 六、現場無人銷售流程模擬

此區用來模擬現場順序，所有操作只產生瀏覽器內的 synthetic event，不會對真實設備送出指令。

| 流程 | 操作方式 | 安全判定 |
|---|---|---|
| 掃描 QR | 填寫 QR／測試訂單識別後按「模擬掃描 QR」 | 驗證失敗或過期時應停止後續流程 |
| 驗證進入 | 選擇「可進入測試／驗證失敗／已過期」 | 非通過狀態不得模擬開門或鎖貨 |
| 開門／解鎖 | 選擇結果後按「模擬開門／解鎖」 | 結果未知時轉人工確認，不假設已開門 |
| 鎖定貨道 | 選擇結果後按「模擬鎖定貨道」 | 衝突或未知時停止，不繼續取貨 |
| 取貨／出貨 | 選擇結果後按「模擬取貨／出貨」 | 結果未知時進入 reconciliation，不自動重送 |
| 機台資訊回報 | 填寫溫度、庫存、網路、電源、門鎖、貨道與溫控狀態後按「回報機台資訊」 | 只記錄觀察，不修改正式庫存或設備設定 |

使用完一組現場流程後，可按 **「重設現場流程」**開始下一組。重設只清除頁面流程狀態，不會刪除已下載的檔案。

## 七、自助式測試工作台

### 7.1 儲存基本設定

在「步驟 A｜確認測試設定」填寫測試批次名稱、目的、負責人、設備角色、設備識別、店點／場域、QR、貨道、SKU、初始溫度與初始庫存，再按 **「儲存本次設定」**。

所有正式天來欄位若尚未由文件、設備 owner 或 Dennis 確認，請填 `[TODO: 待人工確認]`。不要為了完成表單而猜測型號、韌體、fault code、Webhook 或控制協定。

### 7.2 十二種可執行情境

| 情境 | 測試重點 | 預期安全處理 |
|---|---|---|
| 正常 QR 開門取貨 | QR 通過、開門、鎖貨、取貨、資訊回報 | 完成一筆 synthetic 正常流程 |
| QR 驗證失敗 | 不合法 QR | 阻擋開門與鎖貨 |
| QR 已過期 | 過期識別 | 立即阻擋後續流程 |
| 門鎖被阻擋 | 驗證通過但無法開門 | 停止流程並保留異常資訊 |
| 門鎖結果未知 | 無法確認門鎖結果 | `MANUAL_REVIEW`，不得假設已開門 |
| 鎖貨衝突 | 貨道或商品保留衝突 | 阻擋取貨，禁止重複鎖定 |
| 取貨結果未知 | 已送出流程但沒有明確結果 | `NEEDS_RECONCILIATION`，不得自動重送 |
| 庫存不足 | 初始庫存為零或不足 | 阻擋鎖貨與出貨 |
| 機台離線 | 設備網路無法使用 | 保留人工處理，不自動出貨 |
| 溫度需注意 | 溫度觀察值異常 | 只回報，不自行套用未確認閾值 |
| 貨道卡貨 | 商品未正常釋出 | 建立處理／補償 intent，不直接退款 |
| 固定資訊回報 | 設備角色、版本、場域等固定資料 | 只收集觀察資訊，不控制設備 |

可勾選需要的情境後按 **「執行已選情境」**，或按 **「執行完整套件」**一次產生十二種結果。執行完成後，步驟 C 會顯示總筆數、通過、需處理、已阻擋，以及每筆 UTC、狀態序列、機台變化與測試編號。

### 7.3 結果判讀

| 結果類型 | 代表意義 | 可否自動重送／出貨 |
|---|---|---|
| `PASS`／正常完成 | synthetic 流程符合預期 | 僅代表模擬結果，不觸發真實設備 |
| `BLOCKED` | 安全條件不成立，流程被阻擋 | 不可 |
| `MANUAL_REVIEW` | 感測、門鎖或結果存在矛盾／未知 | 不可 |
| `NEEDS_RECONCILIATION` | 需查設備狀態或人工確認 | 不可 |
| `COMPENSATION_INTENT` | 確認需要交由核准支付流程評估補償 | T7 不直接退款 |

## 八、匯出與保存測試證據

執行情境後，可按 **「匯出去敏 JSON」**或 **「匯出 CSV」**。匯出檔不包含 customer code、Token、sign、密碼或正式設備憑證。頁面資料只存在瀏覽器記憶體；關閉或重新整理前應先完成匯出。[1] [3]

| 必須保存 | 不得保存 |
|---|---|
| 測試編號／run ID | 主管管理碼 |
| 執行 UTC | 測試授權碼 |
| 設備角色與去敏設備識別 | 天來 Token |
| 測試場域、貨道、SKU | API sign 或完整 query string |
| 情境名稱與狀態序列 | company／token 明文截圖 |
| DNS、TLS、Machine、Commodity 去敏結果 | 天來 raw response body、完整機台或商品清單 |
| 測試人員與 Dennis 覆核結果 | 正式顧客 PII |

建議保存目錄名稱採 `T7_YYYYMMDD_場域_測試編號`，其中只使用可公開於專案證據中的去敏場域名稱。若需要截圖，請避開主管設定區與授權碼欄位。

## 九、常見問題與故障排除

| 畫面或問題 | 可能原因 | 處理方式 |
|---|---|---|
| 網址無法開啟 | 現場網路、DNS 或瀏覽器限制 | 確認使用完整 HTTPS 網址；保留 UTC 與錯誤畫面，交由網路管理人員處理 |
| 按「只檢查 Adapter」顯示設定未完成 | 尚未建立 active credential 版本 | 由 `SUPER_ADMIN` 依第四章處理 |
| 測試授權碼無效 | 授權碼錯誤、過期或已輪替 | 停止嘗試，向主管取得目前核准版本 |
| Machine 成功、Commodity 失敗 | 上游服務、簽章、權限或 endpoint 個別異常 | 保存去敏結果，由主管與天來確認；不要改用未核准 API |
| 主管設定更新失敗 | 管理碼、必填欄位、Adapter 或資料庫狀態異常 | 舊版本仍有效；確認狀態後再執行一次，不把 Token 放到其他欄位 |
| 匯出檔是空的 | 尚未儲存設定或尚未執行情境 | 回到步驟 A 儲存，再執行情境 |
| 重新整理後紀錄消失 | 本頁採 session-only 設計 | 每次重整前先匯出 JSON／CSV |
| preflight 通過但設備沒有動作 | preflight 本來就只讀取，不控制設備 | 依正式實機測試計畫另行執行；不得要求本頁直接出貨 |
| 結果未知 | 設備／流程未提供明確結果 | 維持人工覆核或對帳，不自動重送、不假設退款 |

## 十一、完成狀態與 GATE-06 判定

| 可回報狀態 | 成立條件 | 是否解除 GATE-06 |
|---|---|---|
| `SIMULATOR_VERIFIED` | 瀏覽器 synthetic 情境通過 | 否 |
| `READ_ONLY_CONNECTIVITY_VERIFIED` | 經 TESTER 授權，DNS／TLS／Machine／Commodity 唯讀 preflight 通過並保存去敏證據 | 否 |
| `TEST_DEVICE_VERIFIED` | 已有指定測試機、精確合約、真實操作證據、出貨結果、庫存對帳、例外情境與 Dennis 簽核 | 須經中央 Gate 判定 |
| 正式營運整合核准 | 測試環境轉營運環境已有明確批准、變更紀錄、回滾方案與責任人 | 須另案核准 |

在 `TEST_DEVICE_VERIFIED` 的全部證據未齊全前，網站底部的 `completion_signal=false` 與 `GATE-06=BLOCKED` 應維持不變。唯讀連線成功、模擬情境成功或 Adapter health 正常，都不能單獨代表正式出貨測試完成。

## 十二、憑證與事件處理規則

若主管管理碼、測試授權碼或天來 Token 可能出現在不受控的對話紀錄、截圖、公開檔案或現場共用電腦，應立即停止使用該值，由授權主管執行輪替。輪替後要建立新的 credential 版本、記錄原因，並重新執行一次唯讀 preflight；歷史版本只用於受控回滾，不應把舊 Token 明文另行保存。

任何未知結果、卡貨、感測器矛盾或出貨結果不明，都必須維持 fail-closed。T7 只回報設備事實、狀態序列、reconciliation 與 compensation intent；退款由核准支付 provider／StallPay 流程處理，正式庫存由既有 ERP inventory truth 管理。
