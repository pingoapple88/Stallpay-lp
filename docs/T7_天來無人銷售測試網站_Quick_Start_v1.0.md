# StallPay T7 天來無人銷售測試網站｜Quick Start

| 項目 | 內容 |
|---|---|
| 操作網址 | [https://go.stall.merchcore.ai/t7-test][1] |
| 估計時間 | 純模擬約 5 分鐘；唯讀網路檢查約 2 分鐘 |
| 適用人員 | 高層主管、現場測試工程師、Dennis |
| 模式 | `DEMO_MOCK`＋`READ_ONLY_TEST_ADAPTER` |
| 安全狀態 | `completion_signal=false`、`GATE-06=BLOCKED` |

> **先記住：**本頁可以模擬 QR、開門、鎖貨、取貨、庫存與故障情境，也可以執行天來 Machine／Commodity 唯讀檢查；不會控制真實設備、不修改正式庫存、不直接退款，也不會在結果未知時自動重送。[1] [2]

## 一、純模擬快速開始

| 步驟 | 操作 | 成功畫面 |
|---:|---|---|
| 1 | 開啟測試網址，確認頁首顯示「天來無人銷售測試模式」及 `DEMO_MOCK` | 黃色警示顯示「這是測試頁，不是正式營運頁」 |
| 2 | 捲動到「步驟 A｜確認測試設定」 | 可看到批次、負責人、設備、場域、QR、貨道、SKU、溫度與庫存欄位 |
| 3 | 填完必填欄位，按「儲存本次設定」 | 顯示「設定已儲存」及 `DEMO_MOCK` |
| 4 | 到「步驟 B」保留要測的情境勾選 | 可單選，也可保留全部十二種 |
| 5 | 按「執行已選情境」或「執行完整套件」 | 步驟 C 出現總筆數、PASS、ATTENTION、BLOCKED 與結果表 |
| 6 | 按「匯出去敏 JSON」及「匯出 CSV」 | 瀏覽器下載兩個證據檔；不包含 Token、sign、密碼或授權碼 |

### 必填測試資料範例

| 欄位 | 測試值範例 |
|---|---|
| 測試批次名稱 | `T7-現場驗收-01` |
| 測試負責人 | `Dennis` |
| 設備角色 | 天來貨道機或天來取餐機 |
| 設備識別 | 現場可核對的測試機編號；未知填 `[TODO: 待人工確認]` |
| 店點／場域 | 現場測試地點代碼 |
| QR／測試訂單識別 | 本次測試專用識別 |
| 貨道 | 例如 `A01`；正式值不確定時填 `[TODO: 待人工確認]` |
| SKU | 測試商品代碼 |
| 初始溫度／庫存 | 現場觀察值或明確標示的 synthetic 值 |

## 二、唯讀網路檢查快速開始

唯讀檢查與情境模擬互相獨立。若只需要展示十二情境，可以不輸入任何管理碼或授權碼。

| 步驟 | 操作人 | 操作 | 預期畫面 |
|---:|---|---|---|
| 1 | 任一測試人員 | 按「只檢查 Adapter」 | 顯示 Adapter 可用或「設定未完成」 |
| 2 | 高層主管 | 若設定未完成，展開 `SUPER_ADMIN`，輸入主管管理碼、Company、Token、變更原因，按「儲存新版本」 | 顯示 active version、遮罩 company、`token=已設定` |
| 3 | 現場測試工程師 | 回到網路 Preflight，輸入測試授權碼 | 授權碼只用於本次請求，不保存、不匯出 |
| 4 | 現場測試工程師 | 按「執行真實唯讀網路檢查」 | DNS、HTTPS／TLS、Machine API、Commodity API 更新 |
| 5 | Dennis | 保存 UTC 與去敏結果 | 只能標示 `READ_ONLY_CONNECTIVITY_VERIFIED`，不可標示實機完成 |

> 主管管理碼、測試授權碼與天來 Token 不可貼入一般對話、測試備註、截圖或 JSON／CSV。主管設定後，敏感輸入欄位會清空。[2]

## 三、十二種情境怎麼選

| 想驗證的問題 | 選擇情境 |
|---|---|
| 正常流程是否完整 | 正常 QR 開門取貨、固定資訊回報 |
| QR 是否會正確阻擋 | QR 驗證失敗、QR 已過期 |
| 門鎖異常是否安全停止 | 門鎖被阻擋、門鎖結果未知 |
| 貨道與庫存是否避免重複動作 | 鎖貨衝突、庫存不足、貨道卡貨 |
| 未知結果是否禁止自動重送 | 取貨結果未知、機台離線 |
| 機台觀察值是否留下待確認紀錄 | 溫度需注意 |

完整套件的預期統計為 **總筆數 12、PASS 2、ATTENTION 5、BLOCKED 5**。這個統計只代表 synthetic 情境產出，不代表真實設備已驗證。

## 四、結果判讀與停止規則

| 結果 | 意義 | 現場動作 |
|---|---|---|
| `PASS` | 模擬流程符合預期 | 保存證據；不可宣稱實機通過 |
| `BLOCKED` | 安全條件不成立 | 停止後續流程，不嘗試繞過 |
| `ATTENTION` | 需要人工覆核或對帳 | 保存狀態序列，交由 Dennis／設備 owner 確認 |
| `NEEDS_RECONCILIATION` | 出貨或取貨結果未知 | 不自動重送、不假設已出貨或未出貨 |
| `COMPENSATION_PENDING` | 已建立補償需求 | T7 不直接退款，交由核准支付 provider 處理 |

## 五、離場前必做

| 檢查 | 完成條件 |
|---|---|
| JSON 已下載 | 內容顯示 `mode=DEMO_MOCK`、`completion_signal=false` |
| CSV 已下載 | 每筆都有 UTC、test run ID、情境、狀態序列與 `gate_06=BLOCKED` |
| 截圖已去敏 | 畫面沒有主管管理碼、測試授權碼、Token、sign 或顧客 PII |
| 異常已標示 | unknown、卡貨、感測器矛盾均保留人工覆核／對帳狀態 |
| Dennis 待辦已記錄 | 唯讀連通、實機出貨、庫存對帳與簽核分開記錄 |
